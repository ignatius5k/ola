## Shared contracts to preserve

1. Use `ROLE` and `WORKFLOW_STATUS` from [`shared/domain.js`](../shared/domain.js). Persist machine values; localised UI labels are separate. SCRUM-38 extends the transition model without changing those spellings silently.
2. `workspace_members` is the current role authority. Approval independently checks that the Reviewer differs from both case creator and submission author. All exposed tables need RLS; ordinary client writes to protected rows are denied. See [permissions](permissions.md).
3. Use UUID internal IDs; keep synthetic `COL-*`/`LED-*` identifiers as source/display IDs. Store money as bounded bigint minor units and send them in JSON as decimal strings. Keep SGD and USD separate; use UTC storage/SGT display.
4. Use code-versioned immutable policy settings and SQL/JavaScript parity tests. A run's stage events are provisional until it completes. A business transition, allocation, audit row and idempotent result commit together.
5. Use the standard `{data,requestId}` / `{error:{code,message,fieldErrors?,currentVersion?},requestId}` envelope. Role, actor, result and timestamp never come from client authority.
6. Planned package choices still require version checks. The current [`package.json`](../package.json) includes React 19.3.1, React DOM 19.3.1, Vite 8.3.5, pinned Supabase CLI 3.0.0 and a pinned embedded PostgreSQL/pgTAP test runtime; it has no authenticated Supabase client, Deno or Playwright dependency. Owners pin exact versions with lockfiles after official documentation, changelog and local `--help` checks. Supabase's current [breaking-change index](https://supabase.com/changelog?types=breaking-change) includes CLI v3 local-by-default behaviour, so SCRUM-39/52 must check target flags before any hosted operation.

## Dependency conflicts resolved here

- SCRUM-38 also proposes `shared/domain.js`; SCRUM-37 creates it, and SCRUM-38 extends/imports it. No second status enum is created in frontend or backend.
- SCRUM-42 owns initial guarded audit writes as part of business transactions. SCRUM-48 completes event coverage, query performance and export. Audit logging cannot be deferred until the Activity screen is built.
- SCRUM-49 can document and test prototype metrics now, but its server-backed acceptance depends on SCRUM-39/42/43/44. The existing [prototype metric definitions](metrics.md) explicitly identify that gap.
- SCRUM-51 may prepare its test plan early, but its full integration gate depends on SCRUM-40–50. Passing local prototype tests alone cannot mark it complete.
